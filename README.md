# Palette Studio · TekiDeki

A colour studio that runs entirely in the browser. Pull a palette out of a photograph, build harmonies and gradients from it, measure WCAG contrast, and see the whole thing through the eyes of the eight most common colour vision deficiencies. No account, no backend, no CDN, no upload: the image you drop in is decoded in page memory and nothing but the files you download ever leaves your machine.

[Live app](https://tekideki.github.io/Palette-Studio/) · [Apache-2.0](LICENSE) · [Support with a coffee](https://paypal.me/TekiDeki)

## What it does

- **Palette from an image.** Drop a photo, pick a file or press *Demo image*. The pixels are decoded on a canvas, sampled on a bounded grid and clustered with k-means++ (deterministic, seeded). Each colour comes back with the share of the image it covers, and the shares always add up to 100.0, not 99.9.
- **Colour input that behaves.** Hex (`#rgb`, `#rrggbb`, `#rrggbbaa`, with or without the hash), a native picker, H/S/L sliders, R/G/B fields, a random button and a click history. Invalid input is rejected with the exact expected format, never guessed.
- **Seven harmonies.** Complementary, analogous, triadic, tetradic, split complementary, square and monochromatic. Each one is a real hue rotation, computed from the base colour.
- **Tints and shades.** An eleven step scale (50 to 950) generated from the base colour, with the contrast of every step on white and on black, so you can see which step is safe for text.
- **Gradients.** Linear, radial and conic from the saved palette, with up to eight draggable stops and a live CSS preview. Export as CSS or as a self-contained SVG.
- **WCAG 2.x contrast.** The exact ratio between a text colour and a background, checked against the AA and AAA thresholds for normal text, large text and UI components, with a live preview at the real sizes. If the pair fails, the app computes the *nearest accessible* colour: the smallest lightness change that reaches 4.5:1, in whichever direction is shorter.
- **Colour blindness.** All 33 matrices published by Machado, Oliveira and Fernandes (2009), applied in linear RGB, so white stays white and grey stays grey. Eight cards: normal vision, protanopia, deuteranopia, tritanopia, the three partial forms and achromatopsia, each with its prevalence.
- **Export.** CSS custom properties (with `rgb` triplets for modern syntax), Tailwind config, SCSS, JSON (with luminance and both contrast ratios per colour) and an SVG swatch sheet, plus a PNG sheet rendered by the browser canvas. Everything is generated locally and copied to the clipboard or downloaded.
- **Română, English, Srpski (Latin), Српски (Cyrillic).** The language can be changed from the header and is remembered. Serbian Cyrillic is generated by deterministic transliteration of the Serbian Latin table (see `build.py`), never translated separately, so all four locales are structurally identical. A `?lang=ro`, `?lang=en`, `?lang=sr-Latn` or `?lang=sr-Cyrl` parameter overrides the stored choice for that visit.
- **Light and dark theme**, keyboard support (`Ctrl+Z` undo, `R` random, `C` copy), visible focus, screen-reader labels, reduced-motion friendly styles.
- **Works offline** after the first visit: an installable PWA with a cache-first app shell, so the studio keeps working on a plane or in a basement.

## What happens to your image

The file is read with a `File` object, decoded with `createImageBitmap`/`Image`, drawn onto an offscreen canvas, sampled and then forgotten. There is no upload, no fetch, no telemetry. Palettes, gradients and settings are stored in `localStorage` under the `tekideki-palette-` prefix; clearing site data removes them.

If you want to confirm nothing leaves: open DevTools, go to the Network panel, drop a photo. The only request you will see is the image itself coming from your disk.

## How the colour maths works, and where its limits are

- **Contrast** follows WCAG 2.x: sRGB channels are linearised with the 0.03928 threshold, luminance is `0.2126 R + 0.7152 G + 0.0722 B`, and the ratio is `(L1 + 0.05) / (L2 + 0.05)`.
- **Colour blindness** uses the published Machado et al. (2009) matrices at all eleven severity steps. The dichromacy forms use severity 1.0, the `-anomaly` forms use the published 0.5 step. Each matrix row sums to 1 by construction, and the test suite checks that property for all 33 matrices, because that is what keeps neutral greys neutral. The matrices are applied to **linear** RGB (decode, transform, clamp, re-encode); applying them to gamma-encoded sRGB is a common bug that shifts every hue.
- **Palette extraction** quantises pixels to a 5 bit grid and runs seeded k-means++ on what is left. Same image and same settings, same palette, on every run and every machine. It is a good summary of the dominant colours, not a perceptual segmentation: a huge flat background will dominate the result, which is what "dominant" means.
- **Colour names** come from a 42 entry reference table compared in CIE Lab (deltaE76). They are approximations: `#0000ff` is closest to *violet* in that table, not to *navy*.

Honest limitations, stated up front:

- **HEIC/HEIF** is only readable where the browser itself decodes it, which in practice means Safari on Apple platforms. Elsewhere the file is reported as unreadable instead of silently skipped.
- **Very large images** are sampled, not fully clustered: the analysis canvas is capped at 1000 px on the long edge, which is what keeps a 40 MB photo from freezing the tab.
- **The accessibility suggestion** moves lightness only. It keeps the hue and saturation of your colour and returns the closest passing step; a designer may prefer to move the hue instead.
- **CMYK** is a straight conversion for display, not a colour-managed print proof. Real print needs an ICC profile and a press.
- **Achromatopsia** is simulated as the luminance-preserving grey, which is the usual approximation, not a perceptual model.
- **Gradient interpolation** is the browser's own (usually sRGB). It is not CIELAB interpolation, so two distant hues can pass through a muddy middle, which is exactly why the palette matters.

## Formats

Input: any `image/*` the browser can decode. Output: CSS, SCSS, Tailwind config, JSON, SVG, PNG.

## Files

| File | What it is |
| --- | --- |
| `index.html` | The built, self-contained app. This is what GitHub Pages serves. Do not edit by hand. |
| `build.py` | Deterministic build: inlines the sources, generates the Serbian Cyrillic locale, runs the checks, writes `index.html`. |
| `src/template.html` | Markup with four markers (`CSS`, `COLOR`, `PALETTE`, `JS`). |
| `src/styles.css` | All styles, both themes, responsive rules, reduced-motion rules. |
| `src/color.js` | Colour engine: parsing, HSL/HSV/CMYK/Lab, WCAG, CVD matrices, harmonies. |
| `src/palette.js` | Palette engine: sampling, quantisation, k-means++, naming, gradients, exports. |
| `src/app.js` | UI logic, storage, i18n, event wiring. |
| `src/i18n/locales.json` | `ro`, `en` and `sr-latn`; `sr-cyrl` is generated at build time. |
| `tests/logic_test.cjs` | 441 assertions on the engines, the locale tables and the built file. |
| `tests/ui_test.py` | 95 Playwright checks on desktop and touch tablet, zero console errors. |
| `sw.js` | Service worker, offline app shell. `VERSION` is bumped when `index.html` changes. |
| `manifest.json` | PWA manifest, icons, shortcuts. |
| `screenshots/` | Desktop and phone captures used by the README and the manifest. |
| `LICENSE`, `NOTICE` | Apache-2.0 and the third-party notice (there is no third-party code). |

## Develop

```bash
python3 build.py          # writes index.html, prints the sha256
node tests/logic_test.cjs # engine, locale and build checks
python3 tests/ui_test.py  # Playwright end to end, desktop + tablet
```

Playwright is only needed for the UI test:

```bash
pip install playwright
python3 -m playwright install chromium
python3 -m playwright install-deps chromium
```

The build is byte-identical for the same inputs: no timestamps, no random values, no environment data. It refuses to write a file that contains an em dash, an en dash, a byte order mark, unbalanced locale keys, mismatched placeholders, an unsafe `</script` sequence, or a Serbian Latin table that never uses one of the five special letters.

## Limites and privacy, in one sentence

Everything you type, pick or drop stays in this tab and in `localStorage`; the only thing that ever leaves is the file you explicitly download.
